## Domain placement rationale

One urls file = one domain (Batch H/I convention: Batch H put me-scoped `users/me/workspaces/invitations/` under `workspace`; Batch I put me-scoped `users/me/workspaces/:slug/projects/invitations/` + `project-roles/` under `project`). Therefore:

- All 11 `page.py` paths → `domains.page` (new key, `rust_module: "routes/page.rs"`).
- All 16 `user.py` paths → `domains.user` (new key, `rust_module: "routes/user.rs"`). This includes the 3 `/api/users/me/workspaces/:slug/...` graph/dashboard paths (user.py:70,75,80): they are me-scoped (querysets filter `actor=request.user` / `assignees__in=[request.user]`), registered in user.py, and handled by `routes/user.rs` (NOT users_me.rs) — so `user` domain, not `workspace`. State per-row rationale in each entry's `notes`.

**Overlap/dup check (2026-09-09):** existing `/users/me/...` entries are only `/api/users/me/workspaces/invitations/` (workspace), `/api/users/me/workspaces/:slug/projects/invitations/` and `/api/users/me/workspaces/:slug/project-roles/` (project). No string collision with any of the 27 new paths (gate test's duplicate-path check is exact-string). No page paths exist in any domain.

2. Else compare Django view vs Rust handler, timeboxed to (a) status codes, (b) response JSON keys, (c) error strings, (d) permission gates.

6. FE-calls-a-variant-present-in-NEITHER-Django-nor-Rust → do NOT invent an entry; record the observation in the matching entry's `notes`.
7. `fe_pages`: default `[]`; fill ONLY with single-page verification via grep.
