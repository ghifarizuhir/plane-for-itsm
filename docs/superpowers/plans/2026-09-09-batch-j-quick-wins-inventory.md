## Gate reality (verified) — read before executing

`route_inventory_test::implemented_paths_are_registered_in_main_rs` does **exact string match** of `path` against `.route("...")` strings in `main.rs`; only `rust_status == "missing"` is skipped. Consequences:

1. New inventory paths must match main.rs route strings EXACTLY (param names included). `main.rs` registers `estimate-points/:point_id/` but Django's param is `<estimate_point_id>` → J1 does a **zero-behavior rename** `:point_id` → `:estimate_point_id` in `main.rs:709` (axum 0.7 handlers extract by position; param names are cosmetic).
2. The composite work-items path CANNOT be expressed in axum 0.7 / matchit 0.7.3 — verified in matchit source: `find_wildcard` errors `TooManyParams` on `:a-:b` (second `:` inside one segment). `routes/work_item.rs:1210` documents this. So J4 marks the canonicalized entry `shape_mismatch` and makes two small edits to `tests/route_inventory_test.rs`: skip `shape_mismatch` in the registered-path check (no-op for existing entries — all current shape_mismatch paths ARE registered) and update the BASELINE string to the canonical path.
3. The 2 GPT endpoints have NO rust handler and NO main.rs route → `rust_status: "missing"` (a `shape_mismatch` claim would fail the gate since the path isn't registered).

## Standing rules (from Batch G/H/I)

- One task = one subagent → controller verifies (presence check + gates) → quality-review subagent → next task.
- Status recipe: (a) status codes, (b) response keys, (c) error strings, (d) permission gates.
- `methods` = Django-served; never scope down. `fe_pages: []` default. `fe_evidence` entries must satisfy the tripwire (file exists, method present, URL wildcard-matches the inventory path).
- Commit format: `feat(rs-api): inventory <scope> (Batch J Tn)`; commits touch `parity-inventory.json` (+ the two explicitly-authorized code/test edits in J1/J4 — nothing else).
